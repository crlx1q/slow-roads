# Мультиплеер: возможен ли

Короткий ответ: **в текущем виде — нет**, но не из-за сети, а из-за отсутствия исходников.
Сетевая часть здесь самая простая, а вот показать чужую машину в сцене без доступа к
движку невозможно.

## Что мешает

1. В репозитории лежит только минифицированный билд: `main.ca6b3355.chunk.js` (694 КБ) и
   вендорный чанк (664 КБ). Нет ни `package.json`, ни исходников, ни sourcemap.
2. Чтобы отрисовать вторую машину, нужен доступ к сцене и фабрике транспорта внутри
   бандла. Наружу игра ничего не экспортирует, публичного API нет.
3. GitHub Pages — статика: WebSocket-сервер там не поднять, нужен внешний хост.

## Что при этом реально сделать

### Вариант A. «Колонна» без чужих машин (реалистично сейчас)
Мир в игре генерируется детерминированно: `alea.min.js` — сеедируемый PRNG, из него
растут трасса, рельеф и расстановка объектов. Значит у всех участников с одинаковым
сеедом, сезоном, локацией и погодой **мир абсолютно одинаковый**.

- хост создаёт комнату: `{ seed, location, season, vehicle, hostId }`;
- остальные подключаются и получают те же параметры;
- по сети гоняется только `{ id, name, distance, speed, heading }` 10 раз в секунду;
- в оверлее мода рисуются мини-карта/список: кто где, кто впереди, отрыв в метрах.

Машин друг друга не видно, но совместная поездка, комната и лидерборд работают.
Это надстройка над уже готовым мод-слоем, движок не трогается.

### Вариант B. Настоящий синхронный мультиплеер (нужна большая работа)
Требуется одно из двух:

- **деобфускация бандла**: найти сцену, камеру и контроллер машины, пропатчить их
   и добавить сетевые «призраки». Это недели реверса, и любая пересборка апстрима
   всё ломает (хеши чанков меняются);
- **пересборка игры на three.js**: ассеты (модели, звуки, текстуры, шрифты) в репозитории
   уже есть и переиспользуются, но физика, генерация трассы и рендер пишутся заново.
   Это полноценный проект, зато после него мультиплеер, камера, сохранения и приборка
   делаются нормально, а не оверлеем.

## Если делать вариант A

Сервер: Cloudflare Durable Objects (WebSocket на бесплатном тарифе) либо маленький
Node + `ws` на Fly.io / Railway. Протокол:

```
-> join   { room, name, clientVersion }
<- room   { seed, location, season, hostId, peers[] }
-> state  { distance, speed, heading }      10 Гц
<- peers  [ { id, name, distance, speed } ] 10 Гц
<- bye    { id }
```

Авторитет по параметрам мира — у хоста; клиенты только интерполируют чужие значения.
В `server/worker.js` уже лежит основа на Worker + KV (пока для сохранений) — комнаты
добавляются туда же через Durable Object.

## Порядок работ

1. Найти живые объекты игры (кнопка `F8` в моде уже печатает кандидатов) → телеметрия.
2. Сохранение позиции и продолжение поездки с того же места.
3. Комнаты + «колонна» (вариант A).
4. Только потом решать: реверс бандла или пересборка на three.js (вариант B).
